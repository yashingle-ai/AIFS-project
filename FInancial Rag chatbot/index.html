01 — THE PROBLEM

Financial PDFs weren't
designed for AI.

Six failure modes break a standard vector-database chatbot on a real annual report. QuantX was engineered around each one.

  1. 01

    Tables

    Flat chunking severs the relationship between a row label, its column header and the number in the cell. The metric survives; its meaning doesn't.

  2. 02

    Charts

    A text-only pipeline is blind to bar charts, waterfalls and trend lines — often exactly where the quarter's story is told.

  3. 03

    Context

    Split a 300-page report into isolated fragments and “summarise this document” returns fragments back, never the narrative.

  4. 04

    Retrieval

    “Q2 FY26 revenue” needs an exact lexical hit and semantic understanding of “second quarter”. One index cannot do both.

  5. 05

    Hallucination

    In finance a single invented figure poisons the whole answer. Plausible is worthless; only traceable counts.

  6. 06

    Fiscal language

    Users ask for Q2 FY26. The PDF says quarter ended 30-09-2025. Identical meaning, zero lexical overlap.

03 — THE JOURNEY OF ONE QUESTION

Eight stages between
a question and an answer.

This is what separates QuantX from an embedding lookup with a chat box on top.

  1. 01

    Query

    “What was the EBITDA growth in Q2 FY26?” arrives with conversation history attached.

  2. 02

    Decompose & rewrite

    Pronouns and follow-up references are resolved into a standalone retrieval query.

  3. 03

    Fiscal expansion

    Q2 FY26 → quarter ended 30-09-2025. H1 FY26 and bare FY26 expand the same way.

  4. 04

    Intent routing

    Classified FACTUAL, SUMMARY, COMPARISON or PRESUMMARY — each routes to a different retrieval strategy and top-k.

  5. 05

    Hierarchical retrieval

    Chunk, page and document indices are searched independently, then merged and de-duplicated by citation.

  6. 06

    Hybrid fusion

    Dense FAISS and sparse BM25 rankings combine through Reciprocal Rank Fusion: score = Σ 1/(k + rank).

  7. 07

    Cross-encoder rerank

    30 candidates are re-scored by a hosted NVIDIA reranker and trimmed to the top evidence.

  8. 08

    Generate & verify

    The LLM answers under strict grounding rules; malformed citations are repaired against the chunks actually retrieved.

05 — HIERARCHICAL RETRIEVAL

Retrieval at every
level of context.

One index answers one kind of question. QuantX keeps three, each with its own FAISS and BM25 pair, and picks between them by intent.

01

Chunk index

Precise facts, single metrics and individual table cells. Where “what was total income in H1 FY26?” gets answered.

narrow · exact
02

Page index

Page-level summaries that hold a metric together with the sentences around it — the context a lone cell loses.

local · contextual
03

Document index

The global narrative: highlights, segment analysis, trends and risks. Where “summarise this report” is actually answerable.

global · narrative
DENSE FAISS

IndexFlatIP over L2-normalised vectors — cosine similarity, semantic recall.

+ RRF Σ 1/(k + rank)
SPARSE BM25

Okapi ranking with finance-aware tokenisation — exact ticker, date and metric hits.

06 — MULTIMODAL INTELLIGENCE

Charts become
searchable knowledge.

A vision model reads every meaningful image at index time and writes it back as structured text. The cost is paid once, during indexing — never at query time.

INPUT · PIXELS

A bar chart embedded in an earnings deck. To a text-only pipeline this page is empty.

→ LLAMA 3.2 VISION
OUTPUT · STRUCTURED TEXT 
# chart → markdown, written into the index
| Period   | Metric | Value |
|----------|--------|-------|
| Q1 FY26  | Revenue| ...   |
| Q2 FY26  | Revenue| ...   |

Axis labels, legend entries, series names and
the trend description are captured as text —
so the chart is now reachable by both FAISS
and BM25 like any other chunk.

Failures degrade silently: an image that can't be captioned is skipped, never breaking the index run.

07 — HALLUCINATION RESISTANCE

If the evidence isn't there,
QuantX doesn't invent it.

Standard RAG

  1. Question
  2. Single-index retrieval
  3. Weak or off-topic context
  4. Model answers anyway
  5. A confident, unsupported number

QuantX

  1. Question
  2. Hierarchical hybrid retrieval
  3. Cross-encoder reranking
  4. Confidence floor evaluated
  5. Citations validated and repaired
  6. Grounded answer — or an explicit refusal
REFUSAL FLOOR

When the best dense score falls below 0.30 and the best sparse score below 0.60, the system refuses instead of generating. Answers also carry a grounding badge — the strong support chip visible in the screenshots above — so a weakly-supported answer announces itself.
